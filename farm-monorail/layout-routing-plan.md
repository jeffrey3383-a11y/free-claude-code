# Monkey Monorail — Estate Track Layout & Routing Plan

A sizing-and-routing plan for a **Monkey Monorail 7ZDGS-300A** rack-and-pinion
plantation monorail on a Sabah palm-oil smallholding. All product figures, pricing,
and sizing rules come from [`monkey-monorail-bundle.json`](monkey-monorail-bundle.json)
(the single source of truth). The companion schematic is
[`estate-layout.svg`](estate-layout.svg) (open in any browser); it is generated by
[`generate_layout.py`](generate_layout.py) directly from the bundle, so the drawing,
the numbers below, and the bundle stay in sync.

```
uv run farm-monorail/generate_layout.py          # default 5-acre case study
uv run farm-monorail/generate_layout.py 30       # any size; canonical sizes use the validated matrix
```

## 2. Sizing methodology (shape-aware, geometric)

Sabah NCR/NT smallholdings are **road-frontage strips**, typically **1:3 to 1:5**
aspect ratio. The 2026 method sizes the system geometrically from the plot shape; the
legacy "acres × slope density" heuristic is **deprecated** (it underestimated rail
length by 50–150% for realistic strip plots).

| Step | Rule | Bundle field |
|---|---|---|
| Plot shape | `short = √(area / aspect)`, `long = short × aspect`; default aspect **3.0** | `sizing_rules.default_aspect_ratio_sabah` |
| Lanes (mains) | `ceil(short_side / 50 m)` — one main per 50 m of frontage so every palm is ≤25 m from a rail | `lane_spacing_m_optimal`, `worker_carry_m_max` |
| Rail length | `lanes × long_side + lanes × 5 m spur` | `rail_length_formula_geometric`, `spur_per_lane_m` |
| Y-switches | `MAX(2, lanes − 1)` | `switches_formula` |
| Posts | `ceil(rail / 1.5 m) + lanes` | `post_spacing_m` |
| Carts | `locomotives × 3` | `carts_per_locomotive` |
| FFB / year | `acres × 8.6 t` | `sabah_benchmarks_2026.ffb_yield_t_per_acre_per_year` |

**Locomotives — known data caveat.** The bundle's stated formula
`locomotives = MAX(1, CEIL(hectares / 35))` predicts **1 locomotive at every size in
the matrix below**, yet the field-validated matrix specifies **2 locomotives at 30
acres** (12.14 ha). The validated matrix governs (the generator uses it for canonical
sizes; intermediate sizes interpolate linearly). The discrepancy is flagged in
`sizing_rules._locomotives_formula_caveat` and should be resolved by correcting the
formula's divisor in a future bundle revision.

## 4. Network architecture — "parallel mains + road-edge header"

A strip plot is flatter and simpler than a hill cluster; the layout reflects that.

- **Mains (red)** run **up-field along the long side**, one per lane, spaced 50 m
  across the frontage. Each main is the spine a corridor of palms loads onto.
- **Harvester corridors** are the **±25 m** reach either side of each main — the
  shaded bands on the schematic. Keeping `lane_spacing ≤ 50 m` guarantees the
  `worker_carry_m_max = 25 m` rule with no gaps.
- **Header rail (green)** runs **along the road edge** linking every main, so one
  locomotive can reach any lane and deliver to a single transfer point.
- **Spurs (5 m)** connect each main to the header.
- **Y-switches (orange)** sit at each main × header junction (`MAX(2, lanes−1)`).
- **Loading station** (black square + FFB ramp) sits at the centre of the header on
  the estate road — the only lorry-transfer point, so one loading operation runs per
  harvest round.

Why this shape: rack-and-pinion handles grade up to 45°, so on a strip the mains
simply run the depth of the plot; the design problem is **coverage** (every palm
within carry distance of a rail), solved by lane spacing, not grade staging.

## 5. Default case study — 5 acres, moderate terrain

From `default_case_study_5_acres_moderate` (economics) and `sizing_matrix_2026` (the
corrected geometric sizing). The schematic defaults to this case.

- **System:** 503 m Q235 galvanized rack rail · 2 lanes · 1 locomotive · 3 × 300 kg
  carts · 2 Y-switches · ~338 posts @1.5 m · 43 t FFB/yr.
- **Turnkey capex: RM 99,766** (geometric matrix). *The bundle's legacy case-study
  figure of RM 65,624 / 250 m used the deprecated density method and is superseded.*

|---|---:|---:|
| Labour | RM 62,400 (driver + 2 loaders) | RM 21,600 (1 operator, system-wide) |
| Fuel | RM 10,114 (diesel, 35 L/t) | RM 599 (petrol, Yamaha MZ175) |
| Depreciation (10 yr) | RM 13,500 | RM 5,211 |
| Maintenance / tyres / insurance | RM 15,900 | RM 4,380 reserve |
| Road maintenance | RM 15,000 | RM 0 |

| **Total burden** | **RM 121,155 / yr** | **RM 31,790 / yr** |

**Annual saving ≈ RM 89,365.** Payback = RM 99,766 ÷ RM 89,365 ≈ **1.1 years**;
≈ RM 772k net over the 10-year life.

## 6. Harvest-day throughput

From `operational_throughput` and `harvest_day_scheduling`. Cart round-trip ≈ 22 min
per 500 m of rail at ~0.6 m/s, with 4 min field load, 2 min station unload, 2 min
buffer. FFA must reach the mill within 24 h.

| Estate | FFB / round | Cart loads | Operation time | Lorry plan |
|---|---:|---:|---|---|
| 5 ac (1:3) | 1.65 t | 6 | ~1.3 h | 1 × 3-ton |
| 10 ac (1:5) | 3.31 t | 12 | ~3.0 h | 1 × 5-ton or 2 × 3-ton |
| 15 ac (1:3) | 4.96 t | 17 | ~5.3 h | 2 × 3-ton |
| 30 ac (1:3) | 9.92 t | 34 | 6–8 h | 3 × 3-ton or 1 × 10-ton |

Best practice: call the lorry **~30 min before the last cart** so it arrives as the
station fills.

## 7. Adapting to a real plot

`generate_layout.py` is bundle-driven. To size a different estate:

1. Run `uv run farm-monorail/generate_layout.py <acres>`. Canonical sizes
   (5/10/15/30) use the validated matrix; others derive from the geometric formulas.
2. For a non-default plot shape, adjust `default_aspect_ratio_sabah` (or add a row to
   `sizing_matrix_2026`) in the bundle and regenerate.
3. Confirm gradients stay within the **45° rack limit** on a real DEM, and lock cart
   and locomotive counts against the supplier datasheet before procurement.

> All lengths, post counts, and cycle times are **planning-grade** estimates derived
> from the bundle's geometry and Sabah field benchmarks — not a construction issue.
> Sensitive lease/financial data (e.g. showroom rent) is intentionally excluded from
> the committed bundle per `sensitive_data_never_publish`.
